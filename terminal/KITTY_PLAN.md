# Kitty preset proposal

Status: draft, 2026-10-22. This document proposes a migration; it does not install
Kitty, change the default terminal, or remove existing configurations.

## Decision

Use Kitty on Linux and macOS with a small, owned preset inspired by
[Linkarzu's dotfiles](https://github.com/linkarzu/dotfiles-latest/tree/main/kitty).
Borrow the workspace and tab-bar design, not the entire desktop environment.
Keep ordinary OpenSSH and server-side tmux usable from any client, including
Termius on a phone and iTerm2 on a Mac.

Kitty owns local tabs, splits and saved workspace layouts. tmux owns persistent
remote sessions. Do not automatically wrap every local terminal in tmux.
Saved Kitty layouts do not preserve remote processes after disconnection.

## Goals and boundaries

- A consistent, dotfile-managed desktop experience on Linux and macOS.
- Convenient tabs, splits, project selection, searchable scrollback and SSH.
- Preserve the OMP behavior that already works, including multiline input.
- Keep modified keys, bracketed paste, focus events, colours and mouse reporting
  available to modern TUIs without forcing new encodings on legacy applications.
- Preserve current SSH keys, host verification, aliases and keepalives. Do not
  enable agent forwarding or replace fleet configuration generated by
  `borrrk-infra/scripts/borrrk doctor`.
- No desktop-wide dotfiles import, mandatory Neovim distribution, plugin manager,
  automatic dotfile copying to servers, or unrelated window-manager changes.
- Phone access must not require Kitty or the `kitten` executable.

## Source assessment

Reviewed sources on 2026-10-22; upstream links track `main` and may change.

| Source | Reuse or adapt | Exclude or change |
|---|---|---|
| [Kitty config](https://github.com/linkarzu/dotfiles-latest/blob/main/kitty/kitty.conf) | Theme separation, session-aware workspace design, tab/split shortcuts | Personal paths, mandatory startup workspace, macOS automation, broad control-key interception |
| [Custom tab bar](https://github.com/linkarzu/dotfiles-latest/blob/main/kitty/tab_bar.py) | Session label once per bar, program/directory titles, readable active tab | Claude/OpenCode status indicators unless their producers are actually installed; they do not provide OMP status |
| [Key-routing kitten](https://github.com/linkarzu/dotfiles-latest/blob/main/kitty/pass_keys.py) | Evidence of the Neovim-specific navigation design | Do not adopt its Ctrl+h/j/k/l interception; forwarding only for detected Neovim would steal keys from OMP and other TUIs |
| [Catppuccin Kitty](https://github.com/catppuccin/kitty) | Mocha palette as the initial visual preset; standard powerline styling as a simpler alternative | No wholesale theme framework or runtime dependency on another checkout |

Before copying upstream code, record the reviewed commit and verify its license
and attribution requirements. Prefer Kitty's built-in configuration where it
can provide the same behavior without custom Python.

## Proposed preset

| Area | Initial choice |
|---|---|
| Colours | Catppuccin Mocha, isolated from behavior settings |
| Font | Existing MesloLGS NF at 12pt; automatic bold/italic selection, no custom logo font |
| Window | Modest padding, subtle transparency, audible bell disabled; preserve useful native window controls |
| Tabs | Session label and program/current-directory titles; no duplicate or nonfunctional agent badges |
| Local panes | Kitty-native splits with a visible active-pane indication |
| Workspaces | Explicit named project layouts and a picker; no mandatory personal startup session |
| History | 50,000 lines; searchable pager with optional Neovim integration and a normal pager fallback |
| Keyboard | Familiar macOS Cmd actions and explicit Linux equivalents, with application control keys preserved |
| macOS Option | Left Option acts as Alt; right Option retains native character entry |
| Effects | No shaders, cursor trails or rendering-delay tuning by default |
| Remote control | Disabled unless an accepted integration requires it; then use a permission-controlled local socket, not unrestricted TTY control |

Use our existing manifest/profile installation convention. Keep configuration
paths relative to the Kitty configuration directory or based on `$HOME`; do not
inherit `~/github/dotfiles-latest`, `/Users/linkarzu`, Homebrew-only executable
paths, personal project names, or logo fonts.

A session picker should use built-in Kitty facilities where sufficient. Project
lookup must not make zoxide, fzf or Neovim mandatory just to open a terminal.
Quick-access terminals are optional and are not part of the initial cutover.

## Keyboard contract

- Leave Ctrl+B available to tmux. Do not copy Linkarzu's `ctrl+b>...` workspace
  mappings; choose nonconflicting desktop shortcuts instead.
- Leave ordinary Ctrl+h/j/k/l, Alt combinations, Enter and modified Enter
  available to applications. Do not special-case only Neovim for forwarding.
- Scope pane and workspace actions to explicit terminal shortcuts. Document
  their reserved combinations rather than silently shadowing application keys.
- Let Kitty and applications negotiate keyboard support. Do not copy Ghostty's
  Shift+Enter byte override into Kitty without demonstrating that it is needed.
- Keep Ghostty's current OMP bindings unchanged while evaluating Kitty.
- Retain tmux's application-requested extended keys, not `extended-keys always`.
  CSI-u encoding on supported tmux versions does not imply full Kitty keyboard
  protocol support through tmux.

## SSH and phone workflow

From a desktop Kitty window, the enhanced interactive path is:

```sh
kitten ssh atlas-agent
tmux new-session -A -s main
```

The [SSH kitten](https://sw.kovidgoyal.net/kitty/kittens/ssh/) wraps OpenSSH and
bootstraps remote terminfo and shell integration. It writes integration files
on the remote host; it is not a read-only connection enhancement. Do not add
arbitrary `copy` directives or forward Kitty remote control by default.
An optional `s` shortcut may invoke `kitten ssh` inside Kitty; do not replace
`ssh` globally or change noninteractive scripts.

Run the SSH kitten outside local tmux, then attach remote tmux. Upstream documents
multiplexer caveats for the kitten's bootstrap and window identity. Ordinary
OpenSSH remains the supported fallback. Keep the real terminal's TERM outside
tmux and `tmux-256color` inside it; install matching terminfo rather than applying
a global TERM override.

From Termius, iTerm2, or another ordinary SSH client, connect normally and run:

```sh
tmux new-session -A -s main
```

This attaches to the same server-side session. The phone does not need Kitty or
`kitten ssh`. Touch scrolling depends on the phone client's mouse/scroll mode;
Kitty configuration cannot fix that client behavior. Clients with different
viewport sizes can resize a shared tmux window; include a concurrent-attachment
check rather than promising identical desktop and phone layouts.

## Clipboard, graphics and integration limits

- Keep clipboard reads subject to confirmation. Do not grant remote applications
  unrestricted access to desktop clipboard contents.
- tmux uses `set-clipboard on` (owner decision, 2026-10-27, replacing `external`):
  application-originated OSC 52 writes reach the terminal, so a pane program can
  overwrite the clipboard but not read it. Test OMP/editor copy actions on each
  client; a tmux copy does not prove they work.
- Kitty supports richer keyboard and graphics protocols than tmux transparently
  forwards. Preserve direct-terminal access for features requiring those protocols.
- Do not enable unrestricted passthrough to make a capability probe appear to
  succeed. Demonstrate the required image/clipboard path before selecting any
  narrowly scoped passthrough policy.
- Do not import SketchyBar, Claude/OpenCode hooks, Neobean, notes automation or
  media-project scripts as incidental dependencies of the terminal preset.
- OMP tab-status indicators are outside the initial migration. Add them only
  against a real, verified OMP integration contract, not simulated state.

## Migration

1. Check the installed Kitty version on Linux and the Mac against the selected
   configuration features. Inventory existing Kitty files before adopting them.
2. Add the portable preset to this repository and the `workstation`/`mac`
   profiles. Keep server tmux configuration shared across profiles.
3. Exercise Kitty in a separate window without interrupting existing OMP or
   remote tmux sessions. Keep Ghostty usable during evaluation.
4. Verify the acceptance checks below before changing a default launcher.
5. Once adopted, remove the managed WezTerm configuration, manifest entry and
   obsolete documentation. Remove an installed symlink only after verifying that
   it points to our retired file; preserve unrelated user configuration. Do not
   uninstall applications as part of the dotfiles cutover.
6. Choose whether Ghostty remains a documented fallback before removing any of
   its managed configuration. Do not leave two competing automatic tmux layers.

## Acceptance checks

These are planned checks, not claims that the Kitty preset has passed them.

- Open the actual Kitty UI on Linux and macOS; observe font, glyphs, colours,
  tabs, split focus, selection and scrollback. Config parsing alone is not proof.
- Run OMP directly and through remote tmux. Exercise multiline input,
  Shift/Ctrl+Enter where supported, Alt+Backspace, Escape, cancellation,
  bracketed multiline paste, selection/copy, mouse scrolling and resize.
  Do not send model requests merely to test terminal input.
- Check other available TUIs, including an editor and a pager. Preserve ordinary
  legacy input when an application does not request extended keys.
- Over SSH to both the workstation and atlas-agent, scroll terminal output without
  recalling commands into the input line; verify mouse-aware applications still
  receive their own wheel events.
- Verify TERM/terminfo and negotiated colour capabilities on the actual client,
  not only with synthetic terminal responses.
- Verify local clipboard contents after tmux copy and application copy separately.
  Exercise any claimed graphics path rather than inferring support from TERM.
- Attach from Termius and desktop simultaneously; check viewport resizing, scroll
  behavior, detachment, reconnection, and continued remote process execution.
- Verify project/session selection without personal paths or unavailable tools.
- Verify installer adoption on both desktop profiles, backup behavior for existing
  files, and that ordinary SSH scripts are unchanged.

## Evidence already available

The shared tmux changes were exercised over SSH on both machines before this
proposal. Scrolling, mouse-event forwarding and OSC 52 emission were checked.
Application-requested modified keys, unchanged legacy input, bracketed multiline
paste and focus events were also exercised on both hosts.

These checks do not establish Kitty UI rendering, Mac/phone behavior, desktop
clipboard contents, image rendering or end-to-end OMP behavior under Kitty.
No Kitty migration has been performed by this draft.
